## 3. 冻结的产品约束（继承，不改）

- 技术方向：Go 后端 + Windows 展示终端
- 数据原则：离线优先，本地缓存可用
- 网络架构：校内 LAN，权威服务端下发
- 展示对象：公共课程信息、公开公告、教师作业、近期日程
- 展示终端：只读，禁止任何学生交互，禁止触达教师管理后台
- 第一版**不实现**：学生账户、成绩排名、个人考勤展示、在线提交、聊天、AI 功能

## 7. Owner 硬门槛与五项放行门槛（2026-10-15 拍板）

> 核心原则：**「能不能上屏」与「能不能上线」解耦**。试点可启动，但首屏只跑合成/样例数据；
> 真实学生数据上屏，必须满足以下五道门槛全部通过。门槛不可被「试点需要」绕过。

| 门槛 | 内容 | 关联测试 | 判定 |
|---|---|---|---|
| **① 隐私门槛** | 投影层默认白名单；敏感字段禁止输出；`privacylint` 在 CI 强制，绕不过 | T-P01~T-P09 | P0 全 PASS |
| **② 撤回门槛** | 撤回后设备端/缓存/待同步队列/历史版本中目标数据**均按策略清除**；设备离线时**必须明确显示「撤回未完成」**，不得假报成功 | T-P08 / 新增 T-P10 / T-R13 | P0 全 PASS |
| **③ 可靠性门槛** | 断网 / 重启 / 损坏 Bundle / 签名错误 / 磁盘空间不足，均有**可验证的失败行为**（不崩、不白屏、不伪装实时） | T-N01~T-N11 / T-R07 / T-R11 / T-R12 / T-S01 / T-S02 | P0 全 PASS |
| **④ 运营门槛** | 明确内容负责人、发布 SLA、过期规则、无公告时的默认画面 | T-D03 / T-A11 / 运营制度文档 | 制度签字 |
| **⑤ 推广门槛** | 上述全部通过后，再决定是否扩教室；走廊屏另设可视距离/亮度/布线/施工验收 | T-A08 / T-A10 / 现场验收 | Owner 批准 |

### 试点周期定义
- **「一个完整周」为最低试点周期，不是自动放行条件。** 必须覆盖：≥1 个周末断网窗口 + 1 次撤回演练 + 1 次损坏 Bundle 注入 + 1 次签名错误注入。
- 一个周末断网和一次撤回演练有价值，但**不足以证明所有异常路径可靠**。

### 资源投入优先级（Owner 指定）
> 如果现在只投一件事：**先做「数据防火墙」，同时把撤回机制纳入第一阶段**，而不是等投影层完成后再补撤回。
