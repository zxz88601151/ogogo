1. 四层信息架构（L1 Ticker → L4 Shell）

Shell 常驻、永不轮播、永不承载业务数据；内容密度自下而上递减。
层名称职责回答的问题
L4SHELL 常驻层校名 / 区域 / 日期 / 时钟 / 网络·数据时效徽标 / 终端号"我是哪台屏、现在几点、数据新不新"
L3PRIMARY 主区教室屏＝今日课表；走廊屏＝单教学卡轮播"现在 / 接下来是什么"
L2SECONDARY 次区作业 / 日程 / 公告"我今天要关心什么"
L1TICKER 底栏重要·紧急公告滚动条 + 数据时效戳"还有什么在变"
空态原则：区块无数据时必须折叠消失，不允许出现"暂无数据"占位框 —— 公共屏上的空卡片会被误读为故障。

2. 教室屏 profile: classroom　1920×1080（16:9）

观看 1–8 m，停留 30 s–10 min → 允许中等密度、多区块并存。最小正文 24 px。

3. 走廊屏 profile: corridor　舞台区一次仅呈现 1 条信息

观看 3–20 m，停留 3–15 s → 单主题大卡、8 s 轮播、最小正文 40 px、对比度 ≥7:1。
槽位内容停留条件
S1当前/下一节课程大卡10 sD-TB 非空
S2近期日程（未来 7 天内最近 1 条）8 sD-EV 非空
S3作业提醒（最紧急 1 条）8 sD-AS 非空
S4公告（priority 最高 1 条）8 sD-AN 非空
—全部为空 → 仅 Shell + 校训卡（降级态）—所有域空

4. 教室屏 vs 走廊屏：差异配置矩阵

走廊屏不是教室屏的缩小版 —— 它是独立信息架构。

5. 网络与数据时效状态（4 级视觉）

核心原则：旧缓存永不带"实时"标识；STALE ≠ OFFLINE ≠ INVALID。
